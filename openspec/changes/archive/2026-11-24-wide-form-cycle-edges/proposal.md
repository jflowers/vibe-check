## Why

The ripwire-backed Python adapter takes Ca/Ce from ripwire's `--arch` table,
which since redhat-et/ripwire#533 (adopted by `bump-ripwire-pin`, draft PR #96)
counts the member edge of a wide-form import: `from fixturepy import cycle_b`
resolves to both `fixturepy/__init__.py` and `cycle_b/__init__.py`. The
adapter's own directory edge set does not. It name-resolves the `--deps`
`<inc t=>` text, and ripwire records that import as written
(`<inc t="fixturepy"/>`), dropping the imported name. No ripwire output exposes
resolved target files; `cc.json` has only `fan_in`/`fan_out` counts.

The edge set is what `cycles.go` runs Tarjan SCC over, so **a cycle closed only
through a wide-form subpackage import is not reported**, even though Ca/Ce
count the edge that closes it. `bump-ripwire-pin` recorded this as a Risk,
pinned it in `TestMapToModules_RecordedPython` (`fixturepy.wide` Ce=2 but
InternalOut=1), and disclosed it in the README `cycle-approximation` row. It is
not a regression (0.6.9 missed the edge in both places), but `from pkg import
subpkg` is idiomatic Python, and a silently missed cycle can't be caught by a
structural gate.

## What Changes

- **Python member-import light parse**: vibe-check scans Python sources for
  `from <absolute.dotted.base> import <names>` statements (single-line,
  parenthesized multi-line, backslash-continued, `as` aliases; `*` ignored),
  in the same light-parse style as the abstractness and LCOM4 scans. This
  follows the hybrid split: vibe-check supplies what ripwire's output cannot.
- **Member edges join the mapping's edge set**: for each imported name `n`
  whose `<base>/<n>` directory is a module in the `--arch` universe, the
  importing file's module gains an edge to that module. That edge is
  deduplicated with the name-resolved edges and counted in
  `InternalOut`/`InternalIn`, so it reaches Tarjan SCC cycle derivation. An
  edge is added only when ripwire's `--deps` row for the same file lists
  `<inc t="<base>"/>`, which anchors every member edge to a statement ripwire
  itself saw.
- **Ca/Ce stay authoritative from `--arch`**: the light parse never adjusts
  coupling counts. It only completes the edge graph used for cycles and the
  internal counters.
- **Fixture**: a new `fixturepy/ring_a` ↔ `fixturepy/ring_b` pair whose cycle
  closes only through `from fixturepy import ring_b`. Recordings and goldens
  are re-captured with the same ripwire build the parent change pins.
- **Docs**: the README `cycle-approximation` caveat drops the wide-form
  limitation; CHANGELOG notes that Python cycle output can gain cycles across
  this change (a measurement change, not a code change).

## Impact

- **Modified code**: `internal/ripwireadapter/` — new `memberimports.go`
  (scanner) with tests; `mapping.go` (`mapToModules` takes the scanned
  member imports and adds anchored member edges); `assembly.go` (runs the scan
  for Python before mapping); `mapping_test.go`, `assembly_test.go`,
  `integration_test.go`, and any test hardcoding the Python edge set or line
  totals; `testdata/python/src/fixturepy/ring_{a,b}/`, `testdata/recorded/**`,
  `testdata/FIXTURES.md`, `testdata/README.md`, `golden-notes.md`.
- **Unchanged**: `metrics/` (Layer 1), `modulegraph.schema.json`, verdict
  thresholds, the TypeScript path (its `--deps` targets are resolved paths, so
  it has no such gap), the Go adapter, and the ripwire pin. No new
  dependencies.
- **Output**: Python `ModuleGraph.Cycles` can gain cycles that were previously
  missed. Ca/Ce/I/A/D are unchanged. A `diff` across the upgrade boundary can
  report a "new" cycle that existed before; CHANGELOG MUST say so.
- **Base**: branched from `opsx/bump-ripwire-pin` (PR #96) because it depends
  on that change's #533 recordings; it will be rebased onto `main` once #96
  merges and cannot merge before it.
- **Follow-ups (out of scope)**: relative imports (`from ..b import x`, `from .
  import sub`) never produce edges today. ripwire records the target as
  written (`<inc t="..b"/>`) and `resolveTarget` classifies a leading-dot
  target as external. That is a separate, wider cycle-derivation gap (it
  affects the base edge, not only members) and gets its own change. #68
  (`--dump-graph`) stays open as the long-term replacement for both
  name-resolution and this light parse.
